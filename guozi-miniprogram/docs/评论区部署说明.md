# 评论模块 · 部署说明

> **当前状态（2026-11-21）**
> - 云开发环境：cloud1-d2gz0v75xf4962e09，已写进 app.js 的 wx.cloud.init
> - 四个云函数：listComments / submitComment / likeComment / deleteComment 已部署到该环境
> - 集合 comments、comment_likes 由云函数**首次调用时自动创建**（ensureCollections()），控制台不用手工建
> - 还需在控制台补的只有两项（可选）：**索引**（量大才影响速度）与 **安全规则**（客户端不直连数据库，不加也能跑，但建议加）

> 依附于既有内容（一条内容一组评论），**没有发帖入口、没有话题流、没有图片评论**。
> 云开发 + 原生小程序，未使用 uni-app / Taro 等框架。
> 本模块只作测试用，默认没有接进正式详情页。

## 一、文件清单

```
miniprogram/
├─ components/comment-section/          # 评论组件（wxml / wxss / js / json）
├─ pages/comment-demo/                  # 测试页（不改正式页面就能验证全部功能）
├─ cloudfunctions/
│  ├─ listComments/                     # 拉列表（顶层 + 楼中楼 + 点赞数 + 我的点赞态）
│  ├─ submitComment/                    # 发评论 / 回复（含 msgSecCheck + 审核模式）
│  ├─ likeComment/                      # 点赞、取消点赞
│  └─ deleteComment/                    # 删除（本人 or 管理员，连带删子回复与点赞）
├─ database-rules/                      # 四个集合的安全规则 + config 种子文档
└─ app.js                               # 已加 wx.cloud.init（ENV_ID 待替换）
```

## 二、部署步骤

### 1. 开云开发

微信开发者工具 → 工具栏「云开发」→ 开通（选按量付费，个人测试免费额度足够）。

开通后拿到**环境 ID**（形如 `cloud1-2g3abcde4f567890`），替换 `miniprogram/app.js` 里的：

```js
wx.cloud.init({ env: 'ENV_ID', traceUser: true })
```

单环境项目也可以把 `env` 整行删掉，默认走当前环境。

### 2. 建集合

云开发控制台 → 数据库 → 新建集合，建四个：

| 集合 | 用途 |
| --- | --- |
| `comments` | 评论本体 |
| `comment_likes` | 点赞记录（openid + commentId 唯一） |
| `config` | 只有一条 `commentSetting` 文档，控制审核模式 |
| `admins` | 管理员 openid 白名单 |

`contents` 是已有集合，不动。

### 3. 配权限

每个集合 → 权限设置 → **自定义安全规则**，粘贴 `database-rules/` 下同名 JSON 里的 `read` / `write` 两段（`_说明` 字段不用粘）。

一句话原理：**客户端只读，写全部收归云函数**。云函数用的是管理员权限，不受这套规则约束。

### 4. 建索引（重要）

云开发控制台 → `comments` → 索引管理，建两个：

| 索引字段 | 类型 | 用途 |
| --- | --- | --- |
| `contentId`(升) + `parentId`(升) + `createTime`(降) | 普通 | 列表分页查询 |
| `parentId`(升) + `createTime`(升) | 普通 | 子回复查询 |

`comment_likes` 建一个**唯一索引**：`commentId`(升) + `openid`(升) — 这是防重复点赞的第二道锁（代码里也做了先查后写）。

### 5. 部署云函数

右键 `cloudfunctions/listComments` → **上传并部署：云端安装依赖**，其余三个同样操作。

部署完成后在控制台逐个「测试」，可用下面的参数（`event` 直接填 JSON）：

```json
// listComments
{ "contentId": "lychee", "page": 1, "pageSize": 10 }
```

### 6. 开通内容安全（敏感词拦截的前提）

`submitComment` 用的是云调用 `cloud.openapi.security.msgSecCheck`，需要：

1. 小程序后台（mp.weixin.qq.com）→ 开发管理 → 接口设置 → 找到「内容安全」/「security.msgSecCheck」→ **申请开通**
2. 云函数所在环境无需额外配密钥，云调用走小程序的接口权限

未开通时：云调用会报权限错误，代码里默认**放行并打日志**（`FAIL_CLOSED = false`）。要做「校验失败即拦截」，把 `submitComment/index.js` 里这个开关改成 `true`。

### 7. 编译

- 开发者工具 → 详情 → 本地设置：勾选 **ES6 转 ES5** 与 **增强编译**（组件里用了 async/await）
- 打开页面 `pages/comment-demo/comment-demo` 即可测

## 三、管理员权限怎么开

两选一，推荐第一种。

**方式 A：admins 集合（可随时增删）**

1. 控制台 → `admins` → 新建文档，`_id` 填管理员 openid，其他字段随意（比如 `{"name":"管理员"}`）
2. 拿到自己 openid 最快的方式：先在测试页发一条评论，在 `comments` 集合里看那条记录的 `openid`

**方式 B：云函数环境变量**

云开发控制台 → 云函数 → `deleteComment` → 配置 → 环境变量，新增：

```
ADMINS = oXXXXXX-aaaa,oYYYYYY-bbbb
```

改完要**重新部署**该函数才生效。

前端的管理员判断只是按钮显隐（测试页有开关可以模拟），**真正鉴权在云函数里**，改前端参数没有用。

## 四、审核模式怎么切

控制台 → `config` → 文档 `commentSetting` → 改 `auditMode`：

| 值 | 含义 | 行为 |
| --- | --- | --- |
| `after`（默认） | 先发后审 | `isPass: true`，评论立刻进列表；管理员事后在 `comments` 里把违规评论的 `isPass` 改成 `false`，或直接删 |
| `before` | 先审后发 | `isPass: false`，前端提示「已提交，审核后展示」；管理员把该条 `isPass` 改成 `true` 后才出现 |

该文档不存在时按 `after` 处理，不会阻塞发布。

待审评论的批量处理：控制台 → `comments` → 筛选 `isPass == false` → 逐条改字段值。量大时可以在控制台写个云函数脚本批量改。

## 五、接到正式页面

详情页 `pages/detail/detail.json` 加：

```json
{ "usingComponents": { "comment-section": "/components/comment-section/index" } }
```

`detail.wxml` 底部（现有 fixed 操作栏上方）加：

```html
<comment-section id="cmt" content-id="{{item.id}}" page-size="{{10}}" is-admin="{{isAdmin}}" />
```

`detail.js` 里：

```js
onReachBottom() {
  const cmt = this.selectComponent('#cmt')
  if (cmt) cmt.loadMore()   // 触底加载下一页
}
```

注意：详情页现在的底部操作栏是 fixed 的，接上评论区后要给页面底部留白（`padding-bottom`），并且评论输入框弹出键盘时用 `cursor-spacing` 顶起来（组件里已设 `cursor-spacing="24"`）。

## 六、已知边界

- 单条评论最多 200 字（前后端都校验）
- 每条顶层评论的子回复一次最多取 100 条（云开发单次查询上限），超过需要再做子回复分页
- 点赞数用聚合统计，不走冗余计数字段，好处是不会算出负数，代价是列表接口多一次聚合查询
- 删除顶层评论会连带删除其下回复和对应点赞记录
- 举报只弹提示，不做后台工单（按需求范围，未开发举报入库）
